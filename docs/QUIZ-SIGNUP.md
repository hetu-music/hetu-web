# 寻曲结果页的注册引导（计划）

在 `/quiz/result` 上引导访客登录或注册，并让登录用户能保存一份稳定的结果。还没开始做。测验本身的出题规范见 `QUIZ.md`。

## 现状

- 结果页对访客几乎没有登录提示。播放、加入队列要有收听权限（`can_stream`）才显示。访客看到推荐的歌，只能看标题和歌词。
- 结果页没有收藏按钮，登录用户也看不到。`FavoriteButton` 本身在未登录时返回 `null`。
- 登录页支持 `?next=`（经 `safeNextPath` 校验），登录后能回到原页面。
- 结果页地址是 `/quiz/result?a=<答案字母>`，每次打开都按当前题目和曲库重新计算。

## 原则

- **不设门槛。** 不要求注册才能看结果，也不弹窗打断。结果页靠分享传播，从分享链接进来的人看到的是分享者的结果，对他们最重要的入口是「重新寻曲」（已有）。
- **不承诺做不到的事。** 注册不等于能收听，收听权限要另外申请，所以文案里不写「登录后试听」。
- **在用户有兴趣的时候引导。** 优先放在具体的歌旁边，而不是页面上的通用横幅。
- **访客的结果随题库变，登录用户保存的结果稳定。** 访客不占存储，曲库或题目调整后，同一个链接看到的结果会跟着变。登录用户主动保存后，结果定格在保存那一刻。

## 链接

所有结果页都用 `/quiz/result/<乱码>`，不再用 `?a=`。乱码有两种，外观一样，从链接看不出答案，也看不出是哪一种。

| | 长度 | 乱码怎么来 | 打开时 |
|---|---|---|---|
| 未保存的结果 | 7 位 | 由答案编码而成，可逆 | 解码，按当前题目和曲库重新计算 |
| 保存过的结果 | 10 位 | 记录的随机 id | 查表，按快照渲染 |

- 地址栏里的地址就是分享出去的地址（「复制链接」直接复制当前页面地址），站内链到结果的地方也用同一个地址。不另外拼分享专用的链接。
- 做完测验跳到 7 位链接；保存后用 `router.replace` 换成 10 位链接，页面不刷新；个人主页链到 10 位链接。
- 两种都解不出或查不到时，跳回 `/quiz`。
- 功能还没上线，`?a=` 直接去掉，不做兼容跳转。

### 7 位编码

- 每题按选项数做混合进制，12 道 4 选项的题共 24 位；再加 16 位校验，共 40 位，base62 编成 7 位（62⁷ ≈ 2^41.7）。
- 编码前用固定的可逆变换打乱各位（例如模 2⁴⁰ 乘一个奇数常数再异或），让只差一题的两个结果链接也完全不同。
- 只是混淆，不是加密，看过源码的人能解出答案。答案不敏感，够用。
- 校验位挡住手误改坏的链接。不带题目版本：题目调整后，旧链接按新题目解读，这是访客结果「随题库变」的一部分。题目数或选项数变了，校验通不过，跳回 `/quiz`。

## 第一步：结果页加收藏按钮

推荐的每首歌旁边都显示收藏按钮。访客点击时跳到 `/login?next=<当前结果页地址>`，登录后回到结果页，再点一次收藏。

- 给 `FavoriteButton` 加一个「未登录时显示、点击去登录」的变体，只在结果页使用，其他页面行为不变。
- 「去登录并带上当前地址」写成公用的小工具，第三步的保存按钮也要用。
- 收藏的是具体的歌，和结果是否稳定无关，所以这一步不受曲库或题目变动影响。

## 第二步：推荐列表下加一行提示

在推荐列表和「重新寻曲 / 分享」按钮之间，加一行小字和登录、注册链接，不用卡片或弹窗。只对未登录用户显示。

文案：「登录后，可以收藏这几首歌，把这次的气韵留在主页。」（等第三步做完再定稿。）

## 第三步：保存结果

让测验结果对登录用户有用，注册才有说服力。

### 为什么存快照，而不存答案

如果只存答案、每次打开时重新计算，结果会悄悄变化：

| 部分 | 依赖什么 | 曲库变动 | 题目变动 |
|---|---|---|---|
| 主气韵、兼有的气韵 | 答案 + 题目 | 基本不变（约 4.6% 的并列情况要看第一首推荐歌，会受影响） | 会变 |
| 意象倾向、偏爱的意象 | 答案 + 题目 | 不变 | 会变 |
| 推荐的歌 | 答案 + 题目 + 曲库 | 会变 | 会变 |

答案按题目位置编码，题目一改，同一串答案的意思就不同了。所以要存一份当时的快照，展示的是「那一次寻得的结果」。

### 怎么保存

- **用户手动保存，不自动存。** 重测后想留着上一版，不点保存就行。
- **每个用户最多保留 5 条，每次保存新建一条。** 记录写入后不再修改，每条有自己的 10 位 id，分享出去的链接永远是保存那一刻的结果。
- **满 5 条时，再保存会删掉最早的一条。** 保存按钮在满额时提示会替换哪一条（「将替换某年某月的记录」）。被删记录的链接打不开，跳回 `/quiz`。用户也可以在个人主页手动删除记录。
- **同一份答案、同一题目版本只存一条。** 已经存过的，不再新建。
- 结果页的保存按钮：
  - 7 位链接，登录用户：显示「保存」。答案和历史里某一条一致、且题目版本相同时，显示「已保存」，点击跳到那条记录的 10 位链接。
  - 7 位链接，访客：点击跳到 `/login?next=<当前地址>`，登录回来后仍在这个结果页，由用户再点一次保存。不做任何自动保存。
  - 10 位链接：不显示保存按钮，只有「重新寻曲」和「分享」。
- 客户端只提交 7 位编码，服务端解码后重新计算再写入，不信任客户端传来的结果。写法沿用收藏的 API 路由（`withAuth`、CSRF 校验、用户身份的 Supabase 客户端）。

### 存什么

存键名和数值，不存展示文案。文案在渲染时按 locale 生成，简繁切换才能正常。

| 字段 | 说明 |
|---|---|
| `id` | 10 位 base62 随机串，主键，也就是链接里的乱码。不用 `user_id`，避免顺着链接找到用户 |
| `user_id` | 所属用户 |
| `quiz_version` | 保存时的 `QUIZ_VERSION` |
| `code` | 答案，只作留档和判断「已保存」，不用来重算。和 `user_id`、`quiz_version` 一起唯一 |
| `persona` | 主气韵的维度键 |
| `secondary` | 兼有的气韵的维度键，可为空 |
| `profile` | 各维度的 z 分数，`jsonb` |
| `imagery` | 偏爱的意象，`text[]` |
| `song_ids` | 推荐歌曲 id，按顺序，`int[]` |
| `percents` | 对应的契合度，`int[]` |
| `created_at` | 保存时间 |

- 索引 `(user_id, created_at)`，个人主页按时间倒序列出。
- 5 条的上限在数据库里保证，不靠应用层先查后删：插入后由触发器删掉该用户第 5 条以后的旧记录，两个并发的保存请求也不会超额。表的总行数不超过用户数的 5 倍。
- 新表要在迁移里显式写 GRANT，并开 RLS：`authenticated` 只能读、插入、删除自己的记录，不给 update。
- 不给 `anon` 任何权限。别人打开 10 位链接时，由服务端用 `getServiceClient` 按 id 读取；如果为此开放公开读，整张表能通过 PostgREST 列出来。

### 代码结构

`getQuizResult` 现在一次算完就输出本地化文案，`persona` 里没有维度键。拆成两半：

- `computeQuizResult(answers)`：只返回键名和数值，也就是快照里的字段。
- `renderQuizResult(snapshot, locale)`：翻译、读取歌曲信息和歌词、跳过曲库里已删除的歌。

7 位链接是 compute 再 render，10 位链接直接 render，保存时只用 compute。

### 怎么展示

- 结果页：10 位链接和 7 位链接长相一样，另外标注「某年某月寻得」。
- 个人主页：新加「气韵」一节（`?tab=quiz`），目录里排在「收藏」之后，默认打开的仍是收藏。左栏卷首不放气韵。
  - 题头右侧放「重新寻曲」。
  - 最近一条展开：主气韵与兼有的气韵、「某年某月寻得」、释义、偏爱的意象、意象倾向、当时契合的歌（小封面、歌名、契合度）。
  - 往次放在「往次」分组下，每条一行：主气韵、兼有的气韵、日期、删除（两步确认）。
  - 每条都链到自己的 10 位链接。
  - 没有记录时，一句楷体灰字说明保存的方法。
  - 原型见 `/lab/profile-quiz` 的 A 方案右栏（`src/components/lab/ProfileQuizProto.tsx`），实现后删掉。
- 曲库里被删掉的歌直接跳过不显示。

## 实施顺序

1. 链接改成 `/quiz/result/<乱码>`，先只有 7 位编码。
2. 第一步：收藏按钮。
3. 第三步的后端：拆分 `getQuizResult`，建表，保存接口，10 位链接的读取。
4. 第三步的前端：保存按钮、访客保存后的登录回跳、个人主页的记录列表和删除。
5. 第二步：提示文案。
