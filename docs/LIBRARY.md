# 曲库页

改曲库页（首页）的渲染、筛选或搜索之前读这份文档。界面样式按 `DESIGN.md`。

## 有意的设计

- **动画每次都播。** 搜索、筛选时新出现的卡片播进场动画；翻页时网格的 `key` 带页码，整页重播；卷首的歌曲总数每次变化都有动画。改渲染方式时要保住这几种情况，framer-motion 因此保留。
- **点左上角标志**是「重置筛选 + 回到顶部 + `router.refresh()`」，不整页刷新，播放不中断。
- **不预加载详情页**：歌名链接 `prefetch={false}`。
- **字体不推迟。** 试过首屏先用系统字体、封面到了再换思源，LCP 有改善，但缓存命中时也闪一下系统字体，取消了。首页和其他页面一样，字出现才下载。
- **依赖**：不引入搜索库，不做拼音搜索；`opencc-js` 只在服务端用。

## 加载

### 服务端渲染默认状态

首页是 ISR。服务端把「第一页、不带筛选和搜索」的列表渲染进 HTML，禁用 JS 也能看到。客户端水合时同样按默认状态渲染，挂载后再按地址栏参数筛一次。所以水合期间不能调用 `useSearchParams`（会让整块退回客户端渲染），地址栏一律经 `useUrlState` 读。

不按查询参数在服务端渲染：那样每个请求都要渲染，CDN 存不了整页。

**带参数打开时不闪默认列表**：`reveal.ts` 的内联脚本在地址栏带了影响列表的参数（`url-state.ts` 的 `LIST_PARAMS`：搜索词、类型、年份、各筛选维度、`page`、`view`）时，用 `visibility: hidden` 藏住列表和分页，筛完再显示。

- 只看这份名单，不看「有没有参数」：分享链接常带 `utm_source` 之类，不该让列表藏起来。
- 卷首的歌曲总数不藏，它从全部变到筛选后的数，正是要有的动画。
- 3 秒后无论如何都显示，JS 加载失败时不至于一直是空的。
- 软导航时 Next 先渲染新页面、提交时才改地址栏，新页面第一次渲染读到的是上一页的查询串。所以 `useUrlState` 的快照带着路径，和 `usePathname()` 对不上就当作还没读到。

### 三档加载

| 档 | 什么时候 | 内容 |
|---|---|---|
| 一 | 首屏 | 列表、卷首、工具栏（含搜索框和筛选按钮本身） |
| 二 | 空闲时 `import()` | 搜索内核（含繁转简表）、`engine.ts`、筛选面板（连带 Base UI 的下拉与滑轨） |
| 三 | 要搜时才拉 | 歌词数据（见「歌词数据」） |

- 地址栏带了搜索词、人名或曲风筛选、`advanced`，或者搜索框获得焦点，第二档立即加载。
- 第二档没到时，结果停在上一次（第一次是全部歌），不锁输入；只按类型、年份筛选不用等它。地址栏里的人名先只去掉首尾空白，第二档到了再按归一化重读。
- `eslint.config.mjs` 里有一条规则：曲库页首屏的文件只能引用第二档的**类型**，不能引用值。引用一个常量就会把整个搜索内核拉回首屏。

### 返回时恢复位置

从详情页返回，要等第二档筛完才是原来那一页，所以 `useListReveal` 等筛完后，在同一个 effect 里滚回原位并显示（`scrollTo` 是同步的，下一帧就在原位）。滚回期间卡片不播进场动画，显示时才播。

### 封面

`CoverArt` 的 `sizes` 必填，写封面实际显示的宽度。窄屏一列时故意少报四分之一：手机多是 3 倍屏，照实写会要 1200 px 的图，而新封面原图多在 1280 px 以上，真会给这么大。

网格第一张 `fetchPriority="high"`，第 2–4 张（宽屏首行）与列表前 8 行 `loading="eager"`，其余懒加载。Next 16 里 `priority` 已废弃。

## 地址栏

### 读写：`useUrlState`

全站共用（曲库页、个人中心、后台），取代了 nuqs。

- **读**：`useSyncExternalStore`，服务端快照是空串，水合时自动按默认状态渲染，之后换成真实地址栏；订阅 `popstate` 跟上返回键。
- **写**：原生 `history.replaceState` / `pushState`，Next 会让 `usePathname`、`useSearchParams` 跟着更新。几个参数一起改时合成一次写入；连续改写节流约 50 ms（Safari 限制 `replaceState` 的调用频率，超了直接抛错）。点进歌曲、切换简繁前先 `flushUrlState`。
- 值等于默认值时不写进地址栏。字符串数组按重复参数存（`?artist=甲&artist=乙`），用 `URLSearchParams.getAll` / `append`，名字里有逗号、`&` 都不用转义。
- **每次请求都渲染的页面**（后台列表、歌曲工作区、个人中心）传 `initialSearch`：页面把 `searchParams` 用 `toSearchString` 转成查询串传进来，服务端、水合时都按它渲染，不先闪默认状态。ISR 和静态页面不传。
- **防抖放在输入端**（`useDebouncedDraft`，300 ms）：输入框立刻变，停下才写地址栏；结果直接跟着地址栏走。反过来的话，带 `?q=` 打开链接会先显示未筛选的列表 300 ms。

### 曲库页的参数

**年份**存实际年份，写法与滑轨顺序一致，左新右旧，存成 `{ newest, oldest }`：

| 滑轨 | 地址栏 |
|---|---|
| 2022 到 2018 | `?year=2022-2018` |
| 只有 2018 | `?year=2018` |
| 左端拖到最新一格 | `?year=-2015`（2015 年及以后，曲库加了更新年份的歌也包含） |
| 右端拖到「未知」 | `?year=2015-`（2015 年及以前，加上年份未知的） |
| 只看年份未知 | `?year=unknown` |
| 两端都到头 | 不写 |

写反了（`?year=2018-2022`）也照样认。

**人名、曲风**存归一化后的简体（`normalize()`），简繁两种页面打开同一个链接结果一致。

**多选维度**（曲风、演唱、作词、作曲、编曲）按用户的操作决定怎么存，不按选中数量切换：

- 全选就是不筛选，不写。一个个勾到全部选中也不写。全选的记号只在内存里，刷新后显示成没选，结果一样。
- 一个个勾选的存包含：`?artist=司夏&artist=李萌`。
- 在全选的基础上取消的存排除：`?artistNot=河图`。含义是「当时的全部选项减去这几项」，曲库加了新人也包括在内。同一维度内仍是「或」，所以河图与别人合唱的歌在「除河图外」里照样出现。

不改成短编号：名字本身就是稳定的标识，编号要另维护对照表，还会错位。

## 筛选

筛选维度由 `filters.ts` 的 `FACETS` 一份配置描述，地址栏、选项统计、匹配和界面都由它驱动，加维度只改这一处。同一维度内是「或」，维度之间是「且」。类型是单选、年份是区间，各有写法，但同样从配置读取。

匹配用 `SongMeta` 里归一化后的值；选项列表的显示和计数仍从 `Song` 取，按页面字形。

**会导致零结果的选项置灰**：当且仅当「其他维度的筛选和搜索词，再加上这个选项」一首都没有。只看其他维度，因为同维度再勾只会让结果变多。置灰的不能勾，已选中的不置灰。不显示计数。置灰只在筛选面板展开时算。

**先筛后搜**：兜底看的是「筛完的歌里有没有精确命中」。先在全部歌里搜的话，别的歌里有一句精确命中，筛完一首不剩也不兜底了。置灰仍按全部歌里搜到的算，所以要多搜一次。

## 搜索

搜索内核在 `src/lib/search/`，入口是 `rank.ts` 的 `searchSongs`。没有可搜的字（空串、全是标点）时返回 `null`，调用方照常显示全部。

### 归一化

搜索词和被搜的文本都过 `normalize()`：去掉标点、空格和符号；全角转半角，字母转小写；**繁体逐字转简体**（一个字换一个字，长度不变）。同时记下「归一化后第 i 个字 → 原文第几个字」，高亮时映射回原文。位置表按需算，只给当前页要显示的那十几句算。

繁转简表 `t2s.json` 由 `scripts/gen-t2s-table.ts` 从 opencc-js 的字典生成并提交，客户端只打包这张表（gzip 约 13 KB）。生成方法：`TSCharacters` 里一对一的条目，前面接上 `TWVariantsRev`；本身是简体字的台湾异体字不收（否则「么」会转成「幺」）；链式条目一直转到底。

### 分档

一首歌按命中的最好那一档排序：

| 档 | 条件 |
|---|---|
| 1 | 题名完全相同 |
| 2 | 题名以搜索词开头 |
| 3 | 题名包含搜索词 |
| 4 | 人名完全相同（演唱、作词、作曲、编曲、别署） |
| 5 | 人名包含搜索词 |
| 6 | 专辑包含搜索词 |
| 7 | 题名近似 |
| 8 | 歌词有一整句与搜索词相同 |
| 9 | 歌词有一句包含搜索词 |
| 10 | 歌词兜底 |

- 歌词档按命中句数从多到少、再按第一处命中的位置排；其余保持曲库原有顺序。
- **歌词各档都在元数据各档之后**，歌词数据到达时只在末尾追加结果，已显示的不重排。
- **单字只搜第 1–6 档**，不搜歌词，否则几乎每首都命中。
- **多个词**（空格分开）：每个词都要在某个字段命中，档位取各词最好档位中最差的那个。片段优先选同时含多个词的句子。

### 题名近似

只用于题名，人名、专辑不做（两三个字，错一个就是一半）。

- 单个词至少 4 个字，最多差 1 个字（Damerau 编辑距离：错、漏、多、相邻颠倒各算一个）。
- 可以只对上题名的一段：「倾尽天夏」「倾尽天」都能搜到《倾尽天下》。
- 这个词在第 1–6 档有任何精确命中就不做近似，打对了题名不会带出相近的题名。条件不看歌词，结果不会随歌词到达忽有忽无。

### 兜底

只在精确命中一首都没有、且歌词数据已就绪时启用（设成「少于 3 首」会给打对了的题名带出近似歌词）。把搜索词切成相邻两字的片段，一句至少覆盖 60%、且至少命中 2 个片段才算，每首歌取覆盖率最高的那一句。三个字的词只有两个片段，错一个就到不了阈值，接受搜不到。

列表上方显示一句「未见原句，以下是相近的句子」，片段高亮对上的两字片段。

### 内存结构

- **`SongMeta`**：题名、专辑、各角色人名、别署、曲风，都已归一化。`getSongMeta` 用 `WeakMap` 按 `Song` 对象缓存，每次筛选得到新数组也照样复用。人名按角色分开存，筛选直接用。
- **`LyricsCorpus`**：全部句子归一化后拼成一个字符串，句间用 `\u0001` 隔开，另有每句的起点、所属歌曲、句号。搜索只在这个串上 `indexOf`，再二分定位到句子，命中不会跨句。
- **分段构建**：每四十首左右让出一次主线程（`scheduler.yield()`，不支持时 `setTimeout(0)`），构建期间到来的搜索先只查元数据。台式机一次建完约 25 ms，4 倍降速下最长的长任务 60–90 ms。

### 片段

只有歌词档命中的歌才有片段：显示命中的那一句，最长 32 个字（`SNIPPET_MAX_LENGTH`），太长以命中处为中心截取。命中多句时取最靠前的一句，「等 N 处」始终露在外面。命中的字用正文色，其余是标签的浅灰；不换强调色、不加粗、不用着重号（11px 太小，Safari 还有着重号字体的问题）。

### 歌词数据

`GET /api/public/songs/lyrics-lines?locale=` 返回 `{ id, lines }[]`，按页面字形，句子用 `buildFolio` 切（去掉署名区和说明行，句号与详情页一致）。繁体在服务端逐句转换，句数不变。缓存见 `CACHE.md`；Service Worker 不缓存它。

- 搜索框获得焦点时才拉；地址栏已带搜索词时挂载后立即拉。大多数访客不搜索，所以不空闲预加载（gzip 约 165 KB）。
- 歌词没到时只查第 1–7 档，每页列表末尾标「歌词检索准备中」；一首都没对上时空状态也写这句，到了还是没有才写「没有符合条件的歌曲」。
- 歌词没到之前不纠正页码：结果还会变多，带页码的链接会被错改成第 1 页。

### 后台

后台歌曲列表（`hooks/admin/useSongs.ts`）也用 `searchSongs`，只查元数据，不搜歌词。没有搜索词时按日期从新到旧；有搜索词时按档位排，同档按日期。

### 已知局限

- 三个字以内的题名打错字、人名打错字都搜不到（如「越人哥」）。
- 繁体页按词转换（「视频→視訊」「仿佛→彷彿」），逐字转回去对不上，这类词要用页面的字形输入。约 0.8% 的句子受影响，古风歌词里很少。
- 单字不搜歌词。
