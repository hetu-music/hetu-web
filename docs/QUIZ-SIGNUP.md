# 寻曲结果页的注册引导（计划）

在 `/quiz/result` 上引导访客登录或注册的计划，还没开始做。测验本身的出题规范见 `QUIZ.md`。

## 现状

- 结果页对访客几乎没有登录提示。播放、加入队列要有收听权限（`can_stream`）才显示，收藏按钮（`FavoriteButton`）未登录时直接不渲染。访客看到推荐的歌，只能看标题和歌词。
- 登录页支持 `?next=`（经 `safeNextPath` 校验），登录后能回到结果页。
- 结果页地址只带答案码 `?a=`，每次打开都按当前题目和曲库重新计算。

## 原则

- **不设门槛。** 不要求注册才能看结果，也不弹窗打断。结果页靠分享传播，从分享链接进来的人看到的是分享者的结果，对他们最重要的入口是「重新寻曲」（已有）。
- **不承诺做不到的事。** 注册不等于能收听，收听权限要另外申请，所以文案里不写「登录后试听」。
- **在用户有兴趣的时候引导。** 优先放在具体的歌旁边，而不是页面上的通用横幅。

## 第一步：访客也能看到收藏按钮

推荐的每首歌旁边都显示收藏按钮。访客点击时跳到 `/login?next=<当前结果页地址>`，登录后回到结果页，再点一次收藏。

- `FavoriteButton` 现在未登录时返回 `null`。给它加一个「未登录时显示、点击去登录」的变体，只在结果页使用，其他页面行为不变。
- `next` 要带上完整的 `?a=` 答案码，否则回来时结果页会重定向到 `/quiz`。
- 收藏的是具体的歌，和测验结果是否稳定无关，所以这一步不受曲库或题目变动影响。

## 第二步：推荐列表下加一行提示

在推荐列表和「重新寻曲 / 分享」按钮之间，加一行小字和登录、注册链接，不用卡片或弹窗。只对未登录用户显示。

文案取决于第三步做不做：

- 只做第一步：「登录后，可以收藏这几首歌。」
- 做了第三步：「登录后，可以收藏这几首歌，把这次的气韵留在主页。」

## 第三步：把气韵存进个人主页

让测验结果对登录用户有用，注册才有说服力。

### 为什么存快照，而不存答案码

如果只存答案码、每次打开时重新计算，结果会悄悄变化：

| 部分 | 依赖什么 | 曲库变动 | 题目变动 |
|---|---|---|---|
| 主气韵、兼有的气韵 | 答案 + 题目 | 基本不变（约 4.6% 的并列情况要看第一首推荐歌，会受影响） | 会变 |
| 意象倾向、偏爱的意象 | 答案 + 题目 | 不变 | 会变 |
| 推荐的歌 | 答案 + 题目 + 曲库 | 会变 | 会变 |

答案码是按位置排的选项字母，题目一改，同一个答案码的意思就不同了。所以要存一份当时的快照，主页展示的是「那一次寻得的结果」，像一次留下的记录。

### 存什么

存键名和数值，不存展示文案。文案在渲染时按 locale 生成，简繁切换才能正常。

| 字段 | 说明 |
|---|---|
| `user_id` | 所属用户 |
| `quiz_version` | 测验时的 `QUIZ_VERSION` |
| `code` | 答案码，只作留档，不用来重算 |
| `persona` | 主气韵的维度键 |
| `secondary` | 兼有的气韵的维度键，可为空 |
| `profile` | 各维度的 z 分数，`jsonb` |
| `imagery` | 偏爱的意象，`text[]` |
| `song_ids` | 推荐歌曲 id，按顺序，`int[]` |
| `percents` | 对应的契合度，`int[]` |
| `created_at` | 测验时间 |

新表要在迁移里显式写 GRANT，并开 RLS，用户只能读写自己的记录。

### 怎么存

- 结果页加一个「存到主页」的动作（登录用户可见；访客点击走第一步同样的 `next` 登录流程）。
- 客户端只提交答案码，服务端用 `getQuizResult` 重新算一遍再写入快照，不信任客户端传来的结果。
- 重测后再存，覆盖旧记录。

### 怎么展示

- 个人主页显示主气韵、兼有的气韵、偏爱的意象，以及当时推荐的歌，标注「某年某月寻得」。
- 曲库里被删掉的歌直接跳过不显示。
- 放一个「重新寻曲」按钮回到测验。不自动按当前曲库重算，否则记录会悄悄变掉。

## 附：分享链接也有同样的问题

分享链接只带答案码，过一段时间别人点开，看到的歌可能和分享者当时看到的不一样，题目调整后气韵也可能变。内测阶段可以接受。正式上线前如果在意，可以复用第三步的快照：分享时生成一条快照记录，用短链接指向它。

## 待定

- 气韵放在个人主页的哪里：顶部 `ProfileHero` 里展示，还是单独一个标签页。
- 只保留最近一次，还是保留历次记录。
- 访客从「存到主页」登录回来后，是自动保存，还是回到结果页让用户再点一次。自动保存需要在 `next` 里带一个标记参数。
