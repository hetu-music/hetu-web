# 寻曲测验出题指南

改 `/quiz` 的题目、选项文案或标注之前读这份文档。题目都在 `src/lib/quiz/questions.ts`。第五节是题目蓝图：每题四个选项的维度、情绪和意象已经排定，写文案时照着填。

## 一、每个选项由什么组成

```ts
{
  text: "一匹温驯的瘦马，缰绳尚带掌心温热", // 文案（简体，繁体自动转换）
  dims: { caomu: 2, renjian: 1 },         // 维度：主维度 2，副维度 1
  mood: { tone: 1, energy: -1 },          // 情绪：明 +1 / 暗 -1，扬 +1 / 抑 -1
  imagery: ["马"],                        // 招牌意象，可省略
}
```

- **维度**决定结果页的人格（「行遍山河」「情之所钟」……），也是匹配歌曲的主要依据。
- **情绪**只参与匹配，不在结果页展示。
- **意象**参与匹配，并显示在结果页的「你选中的意象」里。

用户作答时**只看得到文案**。维度、情绪、意象都是我们对这段文案的解读，所以每一项都必须能从文字里读出来。这是下面所有约束的出发点。

## 二、硬约束（违反会出错，或让测验明显失衡）

1. **每题 4 个选项。** 测试会检查。作答短串每题占一个字母，选项数也不能超过 8 个。
2. **维度只用 9 个键**（见第四节），主维度记 2、副维度记 1。写错键名会在构建模型时直接报错。
3. **每题 4 个选项的主维度互不相同。** 否则这道题区分不出这两个维度。
4. **每题 4 个选项各占一个情绪象限：明扬、明抑、暗扬、暗抑。** 这样每道题都能完整地反映用户的情绪偏向。不要标 0（"说不清"），标不出来说明文案没写清楚，应该改文案。
5. **情绪必须写在字面上。** 换一个人读这句话，也应该判断出同样的明暗扬抑。靠题目背景、典故来历或"作者本意"推出来的情绪不算。
6. **意象只能用 14 个招牌意象**（见第四节），写错名字会报错。
7. **标了的意象，文字里必须有这个字或这个词。** 标了却没写，结果页会说用户偏爱一个根本没在文字里见过的意象。
8. **只标选项里被"看"的对象，背景和修饰不标。**
   - 标：「江声吞赤壁，帆影过金陵」→ 江河（江是被看的对象）
   - 不标：「尽头似有**绿柳**朱楼的那条」里的柳（修饰）；「满身**风**尘」的风、「**江**湖」的江（词的一部分，不是这个意象）
9. **题干里已经写到的意象，选项一律不标。** 例如逢雨的雨、旧梦的梦、山行的山。人人都会经过这道题干，只给其中一个选项标上，等于让"选了那一项"代表"偏爱这个意象"，这很随意。
10. **每个招牌意象至少出现在一个选项里。** 没有任何选项指向它，用户这一项永远是 0，这个特征就失效了。
11. **没选中的意象会被当成"不太偏爱"。** 这是算法的设定。所以第 7 到第 9 条要严格执行：文字里明明写了花却没标，选了这项的用户反而会被推离花多的歌。

## 三、软约束（影响结果质量）

1. **九个维度各做 5 到 6 次主维度。** 蓝图正好如此，改一个选项的主维度时，要在别处补回来。
2. **同一维度要配不同的情绪。** 每个维度的主维度选项里，明暗两边都要有，扬抑两边也都要有。否则情绪和维度会绑在一起：一选情思就被算成暗，喜欢明快情歌的人就表达不出来。
   - 可以有偏向，但不要比曲库更极端。曲库里情思重的歌约 27% 偏明，情思选项里偏明的不要少于这个比例。
3. **不要让同一对"主维度加副维度"反复出现。** 曾经有 6 个选项是"器用加人间"，而且大多标了酒或剑，结果《掺香》当第一的比例冲到平均值的 8.6 倍。同一组搭配最多出现 2 到 3 次。
4. **副维度也要均衡**，每个维度 5 到 6 次。蓝图已经做到。
5. **每个招牌意象出现 1 到 3 次。** 次数太多，这个意象会盖过维度。
6. **相邻两题不出现同一个招牌意象，题干也算。** 连着两题都写马、都写风，读起来像刻意安排。同一意象出现两次时，最好分在不同的情绪象限，否则「偏爱这个意象」会和某种情绪绑在一起。题干与紧接着的选项意境连贯时可以例外（如逢雨之后歧路的雨）。
7. **文案长度**：选项最好在 22 字以内，手机上一般不超过两行。
8. **人称**：说到另一个人时用"那人""一个人""故人"，不用"他"或"她"。
9. **尽量写原创句子，少直接引用名句。** 名句的情绪和意象往往有固定解读，和我们的标注容易打架，也会让熟悉出处的用户按出处而不是按感受来选。
10. **题干要承上启下**，让 12 道题读起来是一段连续的旅程。调整顺序时，前后题干的衔接也要跟着改。

### 情绪的四个象限

站内歌曲的基调也是这样分的，选项情绪要和这套分类对得上：

| 象限 | 站内基调                     | 选项里怎么写                             |
| ---- | ---------------------------- | ---------------------------------------- |
| 明扬 | 豪迈、欢快                   | 痛饮、策马、一日千里、开得正盛           |
| 明抑 | 洒脱、温柔                   | 听雨一下午、刚抽新叶、笑着说家常         |
| 暗扬 | 悲怆、执守                   | 烧掉、去追、报仇、等多久都行、剑在人在   |
| 暗抑 | 思念、离愁、孤寂、怅惘、苍凉 | 睡不着、花都谢了、没人会再翻开、人去楼空 |

有两点容易弄错：

- **洒脱属于明抑，不是明扬。** "写在云上，风一吹就散"这类句子是轻的，不是激昂的。
- **执守属于暗扬。** "守着一座楼，等多久都行"看起来很静，但在站内体系里是有力量的，要写出那股不肯放下的劲。

### 招牌意象

都是候选池中覆盖较广的具体母题。岁月、人间之类覆盖也高，但太抽象，不适合作为"你偏爱的意象"展示，所以没有入选。

| 维度 | 招牌意象       |
| ---- | -------------- |
| 天象 | 风、月、雪、雨 |
| 山河 | 山、江河       |
| 草木 | 花、柳、马     |
| 器用 | 酒、灯、剑     |
| 情思 | 梦             |
| 楼台 | 楼             |

- "花"只算花这个母题本身。梅、桃、杏等是单独的母题，写"红梅"不算花。
- 改招牌意象表（`src/lib/quiz/dimensions.ts`）要同时把 `src/lib/quiz/pool.ts` 的 `POOL_VERSION` 加一，否则服务端缓存的候选池不会刷新。改完跑 `pnpm quiz:check`，确认母题名都能在数据库里找到。

## 五、题目蓝图

十二道题的维度、情绪和意象已经排定，填文案时**只写文字，不改标注**：每个格子写一个选项，让这段文字能读出该格的主维度、副维度和情绪象限；意象一栏有字的，选项里必须写到这个意象，并且它是被"看"的对象；空着的格子不要写招牌意象。

这套分配满足第二、三节的全部约束，是用搜索程序在约束下找出来的，再用真实曲库验证过（候选池 291 首，随机作答 2 万次，文案不影响这些数字）：

| -------------------- | --------------- | ----------- |
| 第一契合的基尼系数   | 0.445           | 0.439       |
| 第一契合率最高的单曲 | 1.90%           | 1.27%       |
| 从未当过第一的歌     | 5 首            | 2 首        |
| 人格分布             | 10.0%–12.6%     | 10.1%–12.2% |

（蓝图一列按情绪权重 1.5、2026-10-25 重标后的歌曲基调、排除日期未知的歌后的 291 首、商业作品降权 0.1、文宣作品降权 0.05 计算；旧题目一列是情绪权重 1、重标前、302 首、商业不降权时的数字。降权会把推荐压到其余的歌上，基尼系数随之升高，蓝图在不按类型降权时是 0.383。）

并列变多，是因为各维度分配得更均衡、分数分布更相近。这个问题应该在算法里加一条打破并列的规则来解决，不必为此打乱蓝图。

几条说明：

- 题干沿用旅程的十二站，可以改写，但要保持场景。逢雨、山行、旧梦三题的题干本身就有雨、山、梦，蓝图在这三题里没有标这些意象。改写其他题干时，如果带出了蓝图在这一题里标过的意象，就要换个写法。
- 四个象限在页面上会随机打乱顺序，表里的排列不代表展示顺序。
- 如果某一格怎么写都和场景不搭，不要自行挪动维度：任何挪动都会牵动别处的平衡。把这一格的情况记下来，作为新约束重新搜索一版蓝图。

## 六、改完之后

1. **改版本号**：改了任何选项的文案、维度、情绪或意象，都把 `questions.ts` 里的 `QUIZ_VERSION` 加一。调整了题目顺序也要加。
2. **跑测试**：`pnpm vitest run src/lib/quiz src/lib/server/service-quiz.test.ts src/components/quiz`。如果测试断言了具体的选项内容（比如某个选项含哪个意象），按新题目更新断言。
3. **跑诊断**：`pnpm quiz:diagnose`，用真实曲库做 2 万次随机作答，然后看这几项：

   | 指标                 | 蓝图        | 合格线                       |
   | -------------------- | ----------- | ---------------------------- |
   | 第一契合的基尼系数   | 0.439       | 不高于 0.5                   |
   | 曾获第一的歌曲       | 289 / 291   | 不少于候选池的 95%           |
   | 第一契合率最高的单曲 | 1.27%       | 不高于约 2%（平均值的 6 倍） |
   | 人格分布（作答分析） | 10.1%–12.2% | 每个维度都在 9%–14% 之间     |

   按蓝图填的文案，只要维度、情绪、意象的标注没变，这些数字就和蓝图一致。

   诊断脚本目前不输出人格分布。如果单曲第一率明显偏高，通常是某一对维度搭配反复出现（见第三节第 3 条）。
